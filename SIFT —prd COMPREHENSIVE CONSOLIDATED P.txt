## AGENT ORIENTATION GUIDE

### 1. What Sift Is
Sift is a client-side, browser-based, AI-assisted product discovery and decision-support workspace for growth-stage B2B SaaS teams. It ingests raw, unstructured, multi-channel customer feedback tables (CSV files), cleans and normalizes data locally in browser memory, performs token-aware two-pass semantic clustering via a secure serverless proxy route to a free-tier cloud AI provider, calculates deterministic hybrid weighted priority scores, and generates copy-ready role-tailored execution deliverables (Strategic Rationales for PMs, Engineering Specs for Developers).

### 2. What Must Be Built
* **Browser-Local CSV Ingestion & Schema Mapper:** Parse CSV exports locally using PapaParse, auto-detect metadata headers, and assign stable row IDs (`FB-001`).
* **Data Identity & Quality Engine:** Differentiate 4 identity tiers (`Feedback ID`, `User ID`, `Account ID`, `Cluster ID`). Isolate missing customer tier/ARR as `UNKNOWN` (1.0x weight). Provide dual-reporting for account coverage (`Confirmed` vs. `Estimated`). Render Data Quality Warning Banners if missing metadata exceeds 5%.
* **Two-Pass AI Semantic Clustering Pipeline:** Execute token-aware 50-row batch processing (~8,000 tokens per call) via a secure serverless proxy route to a free-tier cloud AI provider. Perform client-side category grouping and secondary LLM consolidation with explicit `Uncertain Cluster — Review Recommended` flags for ambiguous matches (0.60–0.84 similarity).
* **Deterministic Prioritization Engine:** Calculate Hybrid Priority Scores ($P_c \in [0, 100]$) using normalized interactive calibration sliders (Default: 40% Impact / 40% Frequency / 20% Severity). Matrix plot coordinates ($F_n, I_n$) remain fixed while ranked cards re-sort dynamically at 60 FPS.
* **Dual-View Discovery Workspace:** Render an interactive 2x2 Spatial Priority Matrix alongside a badged, sorted Ranked Insight Card List with deep-dive drawer panels.
* **Evidence Verification & Guardrail Panel:** Execute client-side exact substring verification against raw CSV text in browser memory for all quote receipts. Decouple observations, verified quotes, AI root-cause hypotheses, and proposed investigations. Inject `[NEEDS INVESTIGATION: Technical Context Missing in Source Feedback]` placeholders when context is absent.
* **Action Output Generators:** Produce copy-ready Markdown Strategic Rationales (PM) and Engineering Specs (Dev). P1 scope includes CS Advisory drafts carrying mandatory engineering review disclaimers.

### 3. What Is Explicitly Excluded
* Mandatory persistent SQL/NoSQL databases or server storage.
* Live write-back integrations (Jira, Linear, Intercom APIs).
* Paid third-party data enrichment services or paid infrastructure.
* Direct client-side embedding of private API credentials.

### 4. Which Decisions Are Frozen
All choices documented in MDD v2.0.1 (Section 6.1) and PRD v1.2.1 are locked: ephemeral local memory model, 3-parameter scoring formula, `UNKNOWN` 1.0x weight fallback, exact substring receipt matching, dynamic sliders with fixed matrix coordinates, and strict 5-tier safety decoupling.

### 5. Which Technical Choices Remain Open
* **AI Provider Candidate Selection:** AI inference provider feasibility is marked **`REQUIRES VERIFICATION`** pending execution of a 4-step Google AI Studio smoke test (`TS-018`) against active free-tier candidates (e.g., `gemini-2.5-flash`, `gemini-2.5-flash-lite`, `gemini-3.5-flash-lite`).
* **Serverless Proxy Hosting Platform:** Vercel Serverless Functions vs. Cloudflare Workers Free Tier (both zero-cost options).

# PART I — PRODUCT AND DISCOVERY FOUNDATION

## 1.1 Original Assignment Problem Statement (Verbatim)
> "AI Product Feedback -> Insight Agent
> 
> Companies today collect massive amounts of product feedback through reviews, support tickets, user calls, and surveys. However, most teams struggle to convert this raw, unstructured data into clear, actionable insights.
> 
> Feedback is often noisy, emotional, fragmented, and biased, making it difficult to identify what truly matters. As a result, important signals get missed, and product decisions are driven by incomplete or misleading information.
> 
> Your Challenge:
> Design an AI-powered agent that transforms raw user feedback into prioritized, actionable product insights that teams can confidently act on.
> 
> Core Problem to Solve:
> How might we help product teams identify what truly matters from noisy, biased, and fragmented feedback?
> 
> What Your Solution Should Do:
> - Aggregate feedback from multiple sources such as reviews, support tickets, and user conversations
> - Cluster similar issues and identify recurring themes
> - Go beyond surface-level complaints to identify root causes
> - Prioritize insights based on impact, frequency, and severity
> - Recommend clear actions, not just summaries
> - Provide transparent reasoning behind insights to build trust
> 
> Constraints:
> - Feedback data is noisy, emotional, and often biased
> - Small or skewed sample sizes can lead to misleading conclusions
> - Outputs must be explainable, as product teams may not trust black-box recommendations
> 
> Goal:
> Build a solution that helps teams move from feedback collection to confident decision-making, ensuring that the most important user problems are identified, prioritized, and acted upon effectively."

## 1.2 Assignment Interpretation and Seven Mandatory Operational Requirements
The assignment mandates a transformational decision-support solution to bridge the gap between unstructured multi-channel feedback collection and confident, defensible roadmap execution. Seven mandatory operational capabilities are derived directly from the assignment parameters:

1. **Multi-Source Feedback Ingestion:** Ingest and parse unstructured feedback originating from distinct touchpoints (support tickets, sales call transcripts, public reviews, in-app feedback) via standard CSV exports.
2. **Deep Theme Clustering:** Move beyond keyword tagging to group semantically equivalent feedback items under unified, cohesive thematic clusters.
3. **Root-Cause Identification:** Look beyond surface-level symptom reporting to formulate backing root-cause hypotheses grounded in technical or workflow failure conditions.
4. **Multivariable Prioritization:** Evaluate and score insights dynamically across Impact (revenue/tier weight), Frequency (volume), and Severity (operational blocker level).
5. **Action-Oriented Recommendations:** Avoid passive summarization by generating explicit, role-tailored action recommendations (strategic rationales, engineering specifications).
6. **Explainable Reasoning and Traceability:** Provide transparent mathematical scoring breakdowns and direct line-of-sight back to exact verbatim customer quotes.
7. **Noise, Bias, and Sample Size Safeguards:** Detect, filter, or down-weight non-actionable spam, emotional venting, duplicated entries, or statistically unrepresentative sample sizes to preserve decision quality.

## 1.3 Executive Overview of Sift
Sift is an AI-native product discovery and decision-support workspace designed for growth-stage B2B SaaS teams. Sift ingests unstructured feedback exports (CSV working tables), separates non-actionable spam from emotional but actionable user feedback, semantically clusters recurring issues, formulates root-cause hypotheses, and calculates a dynamic, deterministic Hybrid Weighted Priority Score.

Rather than acting as a static dashboard or simple summarizer, Sift offers a dual-view discovery workspace combining a 2x2 Spatial Priority Matrix with a Color-Coded Card View, driven by interactive calibration sliders. Every insight generated by Sift is traceable to source customer quotes via deterministic row-ID verification, exposes its mathematical formula, and produces copy-ready action outputs: Strategic Trade-off Rationales for Product Managers, Engineering Specs for Developers, and Workaround Advisory Drafts for Customer Success teams (P1).

## 1.4 Product Vision and Mission
* **Product Vision:** To eliminate opinion-driven roadmap debates in product organizations by turning scattered customer feedback into undisputed, evidence-backed execution.
* **Product Mission:** To equip B2B SaaS teams with an intelligent, transparent discovery partner that ingests noisy feedback, isolates true root causes, exposes revenue impact, and delivers actionable specs—ensuring sprint decisions protect ARR and elevate product quality.

## 1.5 Core Problem Definition
Product organizations face a persistent "Data Overload vs. Decision Paralysis" challenge. B2B SaaS companies collect hundreds of monthly customer comments across support tools, sales calls, app reviews, and surveys. Converting this feedback into sprint priorities frequently fails due to three systemic breakdowns:

1. **Loudest-Voice Bias:** Teams over-index on recent, angry, or highly vocal accounts while missing quiet, systemic issues that drive silent churn across the user base.
2. **Symptom vs. Root Cause Confusion:** Traditional tools group surface keywords (e.g., "Search is slow"), forcing teams to guess the underlying technical failure (e.g., "504 API Gateway Timeout on payloads >10,000 records").
3. **The Trust Deficit (Black-Box AI):** Standard LLM tools generate broad bulleted summaries that teams cannot defend in sprint planning because they lack mathematical transparency, source quote receipts, or account-tier context.

## 2.2 P0 Functional Specifications (MVP Core — REQ-001 through REQ-013)

### REQ-001: Ephemeral Browser-Local CSV Ingestion
* **Module:** Ingestion
* **Priority:** P0 (MVP Core)
* **Description:** The system must accept user-uploaded `.csv` files up to 10MB or 2,000 rows via drag-and-drop or file picker and parse them entirely in browser memory using PapaParse without transmitting raw bulk files to persistent storage.
* **Inputs:** File handle from UI dropzone.
* **User Interactions:** User drags `.csv` file onto landing dropzone or selects via file browser.
* **System Responses:** PapaParse reads text stream, auto-detects delimiter (comma, tab, semicolon), validates encoding (UTF-8, UTF-16, ASCII), and renders a row preview modal within 5 seconds for 300 rows.
* **Validation Rules:** Reject non-CSV file types (`.xlsx`, `.pdf`, `.json`) with an immediate UI toast alert. Reject files exceeding 10MB or 2,000 rows with an error banner.
* **Error Cases & Recovery:** If file reading fails or delimiter detection is ambiguous, prompt user to manually select delimiter or choose a valid `.csv` file.
* **Business Rules:** Ephemeral local processing only. Raw CSV text stays in React component state.
* **Dependencies:** PapaParse library.
* **Acceptance Criteria:** 300-row CSV parses in <5 seconds; row array resides in client memory; zero network upload requests made to static server.

### REQ-002: Smart Schema Mapping Engine
* **Module:** Schema Mapping
* **Priority:** P0 (MVP Core)
* **Description:** The system must auto-detect CSV header names using case-insensitive alias matching and present an interactive mapping grid allowing manual column overrides.
* **Inputs:** Array of header strings from parsed CSV.
* **User Interactions:** User inspects pre-populated dropdown mapping grid and selects correct matching column for mandatory and optional fields.
* **System Responses:** Pre-populates dropdowns based on alias dictionaries:
  * `Raw Feedback Text` (Required): `feedback`, `text`, `comment`, `description`, `notes`, `review`, `issue_description`.
  * `Customer Tier / ARR` (Optional): `tier`, `plan`, `arr`, `mrr`, `customer_tier`, `account_type`.
  * `Feedback ID` (Optional): `id`, `uuid`, `row_id`, `ticket_id`, `feedback_id`.
  * `User ID` (Optional): `user_id`, `author_id`, `email`, `submitter`.
  * `Account ID` (Optional): `account_id`, `company`, `org_id`, `domain`, `customer_name`.
* **Validation Rules:** `Raw Feedback Text` mapping is mandatory. If unmapped, disable "Analyze Data" button and highlight dropdown in red.
* **Error Cases & Recovery:** If mandatory column is missing, user can select any column containing text or abort ingestion.
* **Business Rules:** If `Feedback ID` column is missing, system auto-generates stable IDs (`FB-001`, `FB-002`, ...). If duplicate IDs exist, append row suffix (`FB-001_row2`).
* **Dependencies:** REQ-001.
* **Acceptance Criteria:** Schema mapper pre-fills correct alias matches with >90% accuracy on standard export templates; allows manual dropdown override; validates mandatory field.

### REQ-003: UNKNOWN Metadata Isolation Policy
* **Module:** Data Policy
* **Priority:** P0 (MVP Core)
* **Description:** Missing, blank, or invalid customer tier/ARR entries must be strictly classified as `UNKNOWN` and assigned a neutral baseline tier weight multiplier of $1.0$ without fabricating numerical ARR.
* **Inputs:** Parsed column value for Customer Tier.
* **User Interactions:** Automatic background execution during schema validation.
* **System Responses:** Replaces `null`, `""`, `"N/A"`, or unrecognized tier strings with `"UNKNOWN"`. Sets `TierWeight(u) = 1.0`.
* **Validation Rules:** Tiers mapped to recognized buckets: `Enterprise` (3.0), `Pro / Mid-Market` (2.0), `Free / Starter` (1.0), `UNKNOWN` (1.0).
* **Error Cases & Recovery:** Non-standard tier strings (e.g., "Custom Gold") default to `UNKNOWN` (1.0) and render an informational pill in schema preview.
* **Business Rules:** Never guess or impute company ARR. Preserve data integrity by treating unknown accounts identical to baseline free users.
* **Dependencies:** REQ-002.
* **Acceptance Criteria:** All missing tier rows assigned `UNKNOWN` status and 1.0x multiplier; raw dataset values unmodified.

### REQ-004: Data Quality Alert Banner
* **Module:** Data Policy
* **Priority:** P0 (MVP Core)
* **Description:** Display an high-visibility warning banner whenever `UNKNOWN` customer tier or unmapped account rows exceed 5% of dataset rows.
* **Inputs:** Count of `UNKNOWN` tier rows and unmapped account rows.
* **User Interactions:** User reads warning banner on workspace header and clicks "View Quality Details" for row breakdowns.
* **System Responses:** Renders yellow warning banner above workspace cards:
  > *"Data Quality Warning: X% of records lack customer tier or account metadata and are evaluated provisionally (1.0x weight). Priority scores may reflect submission volume rather than verified account revenue."*
* **Validation Rules:** Trigger condition: $(\text{UNKNOWN Rows} / \text{Total Rows}) > 0.05$.
* **Error Cases & Recovery:** Dismissing banner collapses message to a compact header pill.
* **Business Rules:** Transparent data quality reporting prevents PMs from over-interpreting unweighted volume as enterprise revenue risk.
* **Dependencies:** REQ-003.
* **Acceptance Criteria:** Banner renders when threshold exceeded; calculations remain unaffected; banner collapsible.

### REQ-005: AI Semantic Clustering Engine
* **Module:** AI Pipeline
* **Priority:** P0 (MVP Core)
* **Description:** Process feedback rows in token-aware 50-row batches via serverless proxy to generate cohesive problem clusters matching strict JSON output schema.
* **Inputs:** Array of feedback objects `{ feedback_id, text, tier }`.
* **User Interactions:** User clicks "Analyze Data" button.
* **System Responses:** Sends batched HTTP POST requests to serverless proxy route `/api/cluster`. Renders progress bar with batch completion count.

# PART IV — DATA INGESTION, NORMALIZATION, AND IDENTITY MODEL

## 4.1 Local CSV Handling, Format, and Encoding Guidelines
* Parse standard `.csv` files locally via PapaParse. Limit file size to 10MB or 2,000 rows to ensure browser memory performance.
* Auto-detect delimiters (comma, tab, semicolon) and support UTF-8, UTF-16, ASCII encodings.

## 4.2 Header Normalization and Smart Schema Mapping Grid
Headers are converted to lowercase and matched against alias maps:
* `Raw Feedback Text` (Required): `feedback`, `text`, `comment`, `description`, `notes`, `review`, `issue_description`.
* `Customer Tier / ARR` (Optional): `tier`, `plan`, `arr`, `mrr`, `customer_tier`, `account_type`.
* `Feedback ID` (Optional): `id`, `uuid`, `row_id`, `ticket_id`, `feedback_id`.
* `User ID` (Optional): `user_id`, `author_id`, `email`, `submitter`.
* `Account ID` (Optional): `account_id`, `company`, `org_id`, `domain`, `customer_name`.

## 4.3 Four-Tier Identity Isolation Rules
1. `Feedback ID`: Unique row identifier (`FB-001`).
2. `User ID`: End-user submitter identifier.
3. `Account ID`: Paying corporate entity identifier.
4. `Cluster ID`: Assigned grouping identifier (`CLUST-01`).

## 4.4 Missing Metadata & UNKNOWN Customer Tier Policy
Missing or invalid customer tiers are strictly classified as `UNKNOWN`. They carry a default tier weight multiplier of $1.0$ (identical to standard baseline/Free accounts) without assigning forced numerical ARR values.

## 4.5 Missing Account Identity & Provisional Counting Policy
When `Account ID` is missing or unmapped, the system MUST NOT fabricate company identity. It displays dual-reporting: `Confirmed Unique Accounts` (count of verified account IDs) vs. `Estimated Account Coverage` ($U_c = N_c$ assumed provisionally). A warning pill (`Account IDs Unmapped — Frequency Estimated`) is displayed.

## 4.6 Data Quality Alert Banners & Noise Preservation
If `UNKNOWN` customer tier or unmapped account rows exceed 5% of dataset rows, display a Data Quality Warning Banner:
> *"Data Quality Warning: 12% of records lack customer tier or account metadata and are evaluated provisionally (1.0x weight). Priority scores may reflect submission volume rather than verified account revenue."*

## 5.4 Conservative Two-Pass Cross-Batch Theme Reconciliation Protocol

* **Pass 1 (Batch Extraction):** LLM generates preliminary batch clusters with titles, canonical category tags, summaries, severity ratings, and supporting IDs.
* **Pass 2 (Client Category Grouping & LLM Consolidation Pass):**
1. Client groups preliminary clusters by exact `canonical_category` strings.
2. For categories containing $>1$ batch cluster, send a secondary consolidation prompt to the serverless proxy containing cluster summaries and quote IDs (without re-sending raw text).
3. If similarity between two themes is high ($\ge 0.85$), merge them under a unified cluster title, combining member `member_feedback_ids` without duplicates and setting severity $S_c = \max(S_i)$.
4. Additional inference requests during consolidation pass must not exceed 1 request per canonical category group.



## 5.5 Duplicate Source Assignment & Unclustered Fallback Bucket

* **Duplicate Membership:** If an individual `Feedback ID` is assigned to multiple clusters by the LLM, the client reconciliation engine retains it in the cluster with the highest severity or largest membership, stripping duplicates from secondary clusters.
* **Unclustered Fallback:** Any `Feedback ID` present in the parsed CSV that is omitted from all returned clusters is routed to the `Unclustered Feedback` bucket (`CLUST-UNC`, $S_c = 1, P_c = 0$).

## 5.6 Ambiguous Themes & Uncertainty Flagging

When Pass 2 consolidation encounters ambiguous thematic similarity (calculated similarity metric between $0.60$ and $0.84$), the engine MUST NOT forcibly merge the clusters. Both clusters are preserved as separate items and marked with an explicit UI badge: `Uncertain Cluster — Review Recommended`.

## 5.7 Severity Rating Classification Logic

* `Level 1 (Low):` Minor cosmetic friction or visual alignment issue.
* `Level 2 (Medium):` Workflow degraded, but operational workaround exists.
* `Level 3 (High):` Critical workflow blocker, data corruption, or system crash.

## 5.8 API Retries, Exponential Backoff, Partial Recovery State, and Evidence Preservation

Up to 3 retries are executed on HTTP 429/503 errors using exponential backoff ($2^n \times 1000\text{ms} + \text{jitter}$). Permanently failed batches route remaining items to `Unclustered Feedback` and display a partial analysis notice. All raw CSV text and assigned `Feedback ID` entries remain 100% preserved in client memory regardless of API errors.

# PART VI — PRIORITIZATION AND DETERMINISTIC SCORING ENGINE

## 6.1 Mathematical Scoring Specification & Formulas

### 1. Slider Weight Normalization

Given interactive slider inputs $w_{\text{ARR}}, w_{\text{Vol}}, w_{\text{Sev}} \in [0, 100]$:


$$W_{\text{ARR}} = \frac{w_{\text{ARR}}}{w_{\text{ARR}} + w_{\text{Vol}} + w_{\text{Sev}}}, \quad W_{\text{Vol}} = \frac{w_{\text{Vol}}}{w_{\text{ARR}} + w_{\text{Vol}} + w_{\text{Sev}}}, \quad W_{\text{Sev}} = \frac{w_{\text{Sev}}}{w_{\text{ARR}} + w_{\text{Vol}} + w_{\text{Sev}}}$$

## 6.2 Slider Normalization & All-Zero Slider Override Policy

If $w_{\text{ARR}} = w_{\text{Vol}} = w_{\text{Sev}} = 0$, default automatically to approved baseline weights: $W_{\text{ARR}} = 0.40, W_{\text{Vol}} = 0.40, W_{\text{Sev}} = 0.20$.

## 6.3 Metric Component Normalization ($I_n, F_n, S_n$)

$$\text{TierWeight}(u) = \begin{cases} 3.0 & \text{if Enterprise} \\ 2.0 & \text{if Pro / Mid-Market} \\ 1.0 & \text{if Free / Starter} \\ 1.0 & \text{if UNKNOWN} \end{cases}$$

$$I_c = \sum_{u \in U_c} \text{TierWeight}(u)$$

$$I_n = \begin{cases} \frac{I_c}{\max_{k} I_k} & \text{if } \max_{k} I_k > 0 \\ 0 & \text{if } \max_{k} I_k = 0 \end{cases}$$

$$F_n = \begin{cases} \frac{U_c}{\max_{k} U_k} & \text{if } \max_{k} U_k > 0 \\ 0 & \text{if } \max_{k} U_k = 0 \end{cases}$$

$$S_n = \frac{S_c}{3.0}, \quad \text{where } S_c = \max_{i \in \text{Cluster members}} (\text{Severity}_i) \in \{1, 2, 3\}$$

## 6.4 Zero Denominator Policy & Dataset-Wide Comparability

Zero denominators default safely to $0.0$, preventing divide-by-zero errors. Free-tier-only datasets yield $I_c = \sum (1.0) = N > 0$, resulting in $I_n = 1.0$. Scoring is normalized against global dataset maximums across all workspace cards.

## 6.5 Score Rounding, Tie-Breaking, and Critical Blocker Flagging

$$P_c = \text{Round}_1 \left( 100 \times \left[ W_{\text{ARR}} \cdot I_n + W_{\text{Vol}} \cdot F_n + W_{\text{Sev}} \cdot S_n \right] \right)$$


Ties are broken by raw Impact ($I_c$), then Frequency ($U_c$), then Cluster ID. Level 3 Severity items with $U_c < 3$ display a `Critical Blocker (Low Frequency)` red badge.

## 6.6 Worked Numerical Scoring Examples

* **Dataset Max Values:** $\max I = 15.0$, $\max U = 20$.
* **Cluster A Metrics:** $I_c = 12.0$, $U_c = 10$, $S_c = 3$.
* **Slider Weights:** $w_{\text{ARR}} = 50, w_{\text{Vol}} = 30, w_{\text{Sev}} = 20 \implies W_{\text{ARR}} = 0.50, W_{\text{Vol}} = 0.30, W_{\text{Sev}} = 0.20$.
* **Component Calculations:** $I_n = 12.0 / 15.0 = 0.80$, $F_n = 10 / 20 = 0.50$, $S_n = 3.0 / 3.0 = 1.00$.
* **Final Score:** $P_c = \text{Round}_1(100 \times [0.50 \cdot 0.80 + 0.30 \cdot 0.50 + 0.20 \cdot 1.00]) = \text{Round}_1(100 \times [0.40 + 0.15 + 0.20]) = 75.0 / 100$.

# PART VII — EVIDENCE VERIFICATION, TRUST AND RECOMMENDATION SAFETY

## 7.1 Client-Side Substring Quote Verification Engine

Client-side substring matching validates returned LLM quotes against raw CSV text in client memory:


$$\text{Verified} = \begin{cases} \text{TRUE} & \text{if } \text{Snippet} \subseteq \text{RawText}(\text{Feedback ID}) \\ \text{FALSE} & \text{otherwise} \end{cases}$$


Matches receive a green `Verified Quote` badge; mismatches receive a yellow `Unverified / Rewritten` badge.

## 7.2 Five-Tier Safety Decoupling Framework

1. **Customer-Reported Observations:** Surface user complaints.
2. **Verified Source Quotations:** Exact verbatim quote substrings.
3. **AI-Inferred Causes:** Technical root-cause hypotheses.

# PART IX — TECHNICAL ARCHITECTURE AND SECURITY SPECIFICATION

## 9.1 Proposed Ephemeral System Architecture & Data Flow

Client-side PapaParse CSV parser $\rightarrow$ Ephemeral memory state $\rightarrow$ Serverless proxy endpoint $\rightarrow$ Free-tier cloud AI provider $\rightarrow$ Two-pass client reconciliation $\rightarrow$ Deterministic scoring $\rightarrow$ Substring quote verification $\rightarrow$ React dual-view UI.

### Serverless Proxy Endpoint Request Schema (POST `/api/cluster`)

```json

  "$schema": "[http://json-schema.org/draft-07/schema#](http://json-schema.org/draft-07/schema#)",
```

## 9.3 Serverless Proxy Security Model & Request Protection

Serverless proxy (Vercel Serverless / Cloudflare Workers) enforces strict CORS, 2MB request payload limits, model invocation locking, IP rate throttling (10 RPM/IP), sanitized error responses, and zero payload logging. Private API keys reside strictly in encrypted proxy environment variables.

## 9.4 Stateless Processing, Ephemeral Memory, and Data Lifecycle

All state exists purely in browser session memory. Tab closure or clicking "Start New Analysis" flushes all stored memory arrays.
